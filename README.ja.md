## 5つの主要な発見

### 1. 本物の画面は録画しない——完璧なUIを再構築する

Claude動画のすべての「スクリーンショット」は作られたもの。ピクセル完璧なUIモックアップを3Dレンダリングされたデバイスフレーム（MacBook、iPhone、モニター）に合成し、暖色の背景に浮かせる。ブラウザのクロームなし、ブックマークバーなし、通知バッジなし。

**なぜ効くのか：** 視覚ノイズを排除。すべてのフレームがブランドセーフ。誤ったタブも、恥ずかしいブックマークも、来週のアップデートで古くなるUI要素もない。

### 2. 「Less Is More」のフックが最も高い再生数を記録

最も再生の多かった2本の動画（7,790万と6,350万）は同じオープニング：広大な暖色背景の上の小さなアイコン。テキストなし。アニメーションなし。ネガティブスペースと単一の焦点だけ。

これは**認知ギャップ**を生む——脳はフレームを即座に理解できないため、注意力を投入して解読しようとする。0.8〜1.2秒後にプロダクト名がフェードインする頃には、視聴者はすでに引き込まれている。

1,000万再生を記録した10秒動画？同じ原理。極端なミニマリズム。1つの要素。終わり。

### 3. ロゴイントロなし、エンディングCTAなし——絶対に

77本の動画において：
- **0本**がロゴアニメーションで始まる
- **0本**が「今すぐ登録！」などのCTAで終わる

これは意図的なブランドポジショニング。ロゴイントロは「自分たちを紹介する必要がある」。CTAは「あなたが必要だ」。Claudeはどちらもしない——プロダクトが1フレーム目に登場し、動画は暖色背景の静かなロゴへとフェードアウトする。

メッセージ：*私たちのプロダクトは売り込む必要がない。*

### 4. 「結果だけでなく思考過程を見せる」がエンゲージメントを駆動

AIの過程を可視化する動画——タスクリストが緑にチェック、ターミナルコマンドがスクロール、ノードグラフが展開——は、最終結果だけを見せる動画より一貫して高い成果を出す。

これは制作テクニックではない。**トラストアーキテクチャ**だ。過程を見せることで、AIがブラックボックスではなくなる。視なる。視聴者は検証できる：「実際にこれらのステップを実行した」。

最も極端な例：Computer Use（7,790万再生）はClaudeが実際のOSをアプリごとにクリックする様子を見せる。シミュレーションではない。早回ししすぎていない。本物のカーソル、本物のクリック、本物のためらい。

### 5. ハードカットのみ——凝ったトランジション一切なし

77本の動画において：
- ~60% ハードカット
- ~15% 暖色背景へのフェードアウト
- ~10% スライドイン
- ~0% ディゾルブ、モーフィング、3Dフリップ、パーティクルエフェクト

すべてのトランジションは2秒以内。シネマティックなディゾルブなし。派手なモーショングラフィックのトランジションなし。哲学：各フレームが見る価値があれば、カットすることを詫びる必要はない。

## データドリブンのインサイト

### 「Introducing」は「now available」の5倍の再生数

新規発表動画（「Introducing Claude Cowork」など）は平均**2,360万再生**。既存機能の拡張動画（「Claude is now available in Excel」など）は平均**460万**。「Introducing」は単なるコピーではない——「新種」vs「バージョン更新」のシグナルだ。

### 60〜90秒がスウィートスポット——その後は急降下

| 時間 | 平均再生数 |
|------|-----------|
| <15秒 | 300万 |
| 30〜60秒 | 730万 |
| **60〜90秒** | **1,560万** |
| >90秒 | 290万 |

60〜90秒で完全なナラティブアーク（フック → デモ → マジック → リザルト）を展開できる。30秒未満は不完全に感じる。90秒超は注意力が低下する。

### パルスリリース——均一なドリップではない

77本の動画が222日に分散 = 平均2.9日に1本。しかし77%の日にリリースなし。Anthropicは**バーストキャンペーン**を使用——3〜5日のウィンドウで1日2〜3本、その後静寂期。

最も極端なケース：2026年2月に1ヶ月で23本（全コンテンツの30%）、Opus 4.6とCoworkのローンチに集中。最多記録日：2月20日、24時間で7本。

**なぜパルスが効くのか：** プラットフォームアルゴリズムはトピック集中度を評価する。関連動画の集中は「Claudeがどこにでもある」感覚を作り、均一なドリップでは実現できない。

### 幅 vs 深さ：2つの異なるゲーム

- **幅の勝負**（ブランド露出）：Computer Use — 7,790万再生、14,467リツイート。数百万人が見たが、保存した人は少ない。
- **深さの勝負**（開発者ロイヤルティ）：Agent View — 230万再生だが、0.32%のブックマーク率と686件のリプライ。視聴者は少ないが、一人ひとりが深く関与。

両方大事。幅がブランドを築く。深さがコミュニティを築く。Anthropicは2つのトラックを同時に走らせる。

### 月曜日がローンチデー

| 曜日 | 平均再生数 |
|------|-----------|
| **月曜** | **1,260万** |
| 金曜 | 940万 |
| 火〜木 | 470〜550万 |

月曜の投稿は週末から平日への注目波に乗る。金曜の投稿は週末の増幅を得る。

| | Claude | ChatGPT | Gemini | Apple Intelligence |
|---|--------|---------|--------|-------------------|
| メインカラー | 暖白＋テラコッタ | 寒色青＋黒グラデーション | 白＋マルチカラー | 純黒＋純白 |

Claudeのビジュアル言語は、AI業界のデフォルトである寒色ブルーパレットからの意図的な逸脱。温かさ＋知性＝学術的、而非企業的。

## あなたのプロダクトに応用する

**そのまま使える：** ハードカット、ロゴイントロなし、CTAなし、センテンスケースのタイトル＋ピリオド、フォントウェイト500/600/700、タスクシーケンス、3〜8秒シーン、アンチパターンリスト、パルスリリースリズム、60〜90秒スウィートスポット。

**ブランドに合わせて調整：** カラーシステム（ブランドカラーを使いつつ暖色キャンバス＋ダークUIの階層を維持）、タイポグラフィ（ブランドフォントを使いつつサイズ階層を維持）、デバイスモックアップ（3Dレンダリングができない場合はスクリーンショット＋シャドウで代替）。

**基本原則：** すべての制作決定には理由がある。Claudeの選択は恣意的な美学ではない——モーションを通じたブランド戦略の表現だ。理由をコピーし、ピクセルをコピーするな。

# Anthropic Claude 製品ビデオ制作方法論

77本の@claudeai公式ビデオ（2025-10〜2026-05）に基づく体系的分析。
制作パイプライン、デザインシステム、ナラティブフレームワーク、モーション文法、リズムエンジン、エンゲージメント公式を網羅。

---

## 1. 制作パイプライン

### 1.1 コンセプトからリリースまでの6つのステージ

```
Brief → Storyboard → UI Fabrication → Animation → Audio → Delivery
```

**ステージ1：Brief（クリエイティブブリーフ）**
- ビデオタイプの決定（第3章ナラティブフレームワーク参照）
- 所要時間の決定：30s / 60s / 90s / 10s ショートカード
- チャネルの確認：X/Twitter（16:9 または 1:1）、YouTube（16:9）、Instagram（4:5）
- オープニング戦略の選択（第5章Hookアーキテクチャ参照）

**ステージ2：Storyboard（絵コンテ）**
- 従来の手描き絵コンテは作らない——UI mockupツールで直接シーンを配置
- 各シーンにタイムコード、内容説明、モーションタイプ、トランジション方法を記載
- Claudeのアプローチ：シーン粒度が細かい（3-8秒/シーン）、各シーンで1つのことのみ実行

**ステージ3：UI Fabrication（インターフェース製造）**
- **コア原則：実際の画面を録画せず、完璧なUIを再構築する**
- Figma/Sketch/After Effectsでピクセル単位のプロダクトインターフェースを再構築
- ノイズを全て除去：無関係なタブ、デバッグ枠、余計な通知バー、実データの汚いデータ
- デバイスフレームは3Dレンダリングmockup（iPhone、MacBook、ディスプレイ）を使用、微妙なドロップシャドウ付き
- これはAnthropicビデオと競合の最大の差異点：全フレームが完璧

**ステージ4：Animation（モーション）**
- すべての動きはコンテンツアニメーション由来、カメラ移動ではない
- シーン間のトランジションはハードカットが主、複雑なトランジション（< 2秒）は時折使用
- カーソル移動のシミュレーション——起点を設定、0.46秒前にopacity 0→1、ターゲットへ飛行、クリックパルス
- Task Sequenceが1行ずつ入場、ステータス色変更、チェックマーク

**ステージ5：Audio（オーディオ）**
- 高速リズム動画ビデオ：ビート同期のエレクトロニック/パーカッションBGM
- プロダクトデモ：環境軽音楽
- ターミナル/開発者ビデオ：最小限または無音
- ブランドステートメント：無音または単一トーン
- オリジナル無音版を保持し、別途BGM付き版を書き出し

**ステージ6：Delivery（納品）**
- 複数解像度で書き出し：4K（3840x2160）はフラッグシップ用、1080pは通常用
- 複数アスペクト比：16:9横向きが主、4:5縦向き / 1:1正方形はソーシャル用
- ファイル名規則：`YYYY-MM-DD-slug-keyword.mp4`

### 1.2 二つの制作トラック

| トラック | 投入 | 特徴 | 典型的用途 |
|----------|------|------|-----------|
| **公式高品質** | 高 | 4K、シミュレートUI、合成デバイスmockup、モーショングラフィックス | プロダクトローンチ、主要機能 |
| **コミュニティ/ライブ** | 低 | 生のスクリーン録画、実人物出演、最小限のポストプロダクション | ハッカソン、コミュニティイベント、実際のデモ |

二つのトラックは並行して運用。ライブコンテンツが時折最高のエンゲージメントを獲得（Coworkライブデモ 14.6M）——「リアル感」自体が希少資源だから。

## 2. デザインシステム

### 2.1 カラーシステム：「ウォームインテリジェンス」

```
キャンバス背景：  #FBFAF6 ~ #F5F0E8  ウォームホワイト/クリーム（純白ではない）
プロダクトサーフェス：  #1A1A2E ~ #2D2D3D  ダークモードチャコール
プライマリアクセント：  #D67C64            テラコッタ/バーンドオレンジ
セカンダリアクセント：  #4ECDC4            ターコイズ/シアン
テキストダーク：  #0F172A / #1A1A1A
テキストライト：  #FFFFFF / #E0E0E0
```

**デザイン意図：**
- ウォームホワイト ≠ 純白。ウォームホワイトは「紙のような」質感を生み出し、純白より上品で、純白より柔らかい
- テラコッタは最も即座に認識可能なビジュアル要素——一瞬でClaudeだとわかる
- ダークモードUI = 「ハイエンド」「テクニカル」「フォーカス」を暗示
- 競合の冷たいブルー/ブラックグラデーション（OpenAI/Google）や純黒白（Apple）から全体的に距離を置く
- ウォーム + インテリジェンス = 学術感、而非企業感

**競合とのポジショニング差異：**
- OpenAI：冷たいブルー + ブラックグラデーション → テック感/クール
- Google：白 + 多彩 → 親しみやすい/コンシューマー向け
- Apple：純黒 + 純白 → ミニマル/プレミアムコンシューマー
- Claude：ウォームホワイト + テラコッタ + ダークUI → 学術/思考/温もり

### 2.2 フォントシステム

| 用途 | フォントスタイル | ウェイト | 特徴 |
|------|----------------|---------|------|
| タイトルカード/ブランド | ハイコントラストセリフ体（Editorial New スタイル） | 700 | 文節式大文字小文字＋ピリオド |
| UIラベル/本文 | ジオメトリックサンセリフ体（Inter/SF Pro） | 500-600 | クーンで読みやすい |
| コード/ターミナル | 等幅体（JetBrains Mono） | 400-500 | 構文ハイライト |
| オールキャップスラベル | サンセリフ体 | 600 | "PROGRESS", "CONTEXT" |

**重要なディテール：**
- タイトルは文節式大文字小文字（sentence case）を使用、タイトル式大文字小文字（Title Case）は使用しない
- タイトル末尾にピリオド——会話感と自信感を生み出す："Claude now integrates."
- ウェイトは500 / 600 / 700のみ使用、合成太字は禁止（`font-synthesis: none`）

### 2.3 デバイス Mockup 言語

デバイスmockupは最もコアなビジュアル装置であり、装飾ではない：

```
┌─────────────────────────┐
│                         │
│   ┌─────────────────┐   │
│   │  [プロダクトUI]   │   │  ← 3Dレンダリングデバイスフレーム
│   │  ダークモード界面  │   │     微妙なドロップシャドウ付き
│   │                 │   │     box-shadow: 0 8px 32px rgba(0,0,0,0.12)
│   └─────────────────┘   │
│                         │  ← ウォームホワイト/クリームキャンバス
└─────────────────────────┘
```

**複数スクリーンの同時表示に関する3つのコンポジション：**

**A. 中央デバイス** — 単一フォーカス、機能アナウンスに適する
**B. 分割画面レイアウト** — 左Agent + 右ターゲットアプリ、インテグレーション表示に適する
**C. 空間ナラティブ** — スマートフォン → 落書き接続 → デスクトップ、クロスデバイスフローに適する

## 3. ナラティブフレームワーク

### 3.1 4つのコアナラティブモード

#### モードA：標準機能アナウンス（30-60s）— 最も一般的

```
Hook    (0-3s)   機能名/アイコンがウォーム背景上にリビール
Context (3-8s)   問題またはユーザー需要を表示
Action  (8-15s)  ユーザーが操作をトリガー（クリック/入力）
Demo    (15-45s) アニメーションプロダクトデモ（コアコンテンツ）
Magic   (30-50s) システムが自動完了（Task Sequence/進捗ビジュアライゼーション）
Result  (45-55s) 完了後のステータスを表示
Close   (55-60s) Logo + ウォーム背景でクローズ
```

適用：大多数の機能リリース。77本のビデオの約60%を占める。

#### モードB：エコシステムスキャン（30-50s）

```
Hook  (0-3s)   "[プロダクト] connects to [ツール/ワークフロー]"
Setup (3-8s)   ターゲットアプリケーションを表示（Slack/Excel/Figma）
Flow  (8-35s)  複数アプリ間の切り替え、データフローの表示
Proof (35-45s) 最終結果ステータス
Close (45-50s) Logo
```

適用：インテグレーションアナウンス、パートナーシップ表示。重要なビジュアル装置は分割画面 + @mentionトリガー。

#### モードC：超ショートソーシャルカード（8-15s）

```
単一シーン：ブランド背景 + アニメーションテキスト/アイコンリビール
プロダクトデモなし、純粋なブランド/アナウンス情報
```

適用：イベントプロモーション、短いアナウンス、ブランドステートメント。「Thank You」（8.2秒 12.7Mビュー）がこのモード。

#### モードD：開発者向けディープデモ（60-90s）

```
Hook        → ターミナルがすでに実行中（フラッシュフォワード法）
Setup       → ユーザーがアドバンスドコマンドを入力
Execution   → ターミナル出力 + 分割画面プレビュー
Magic       → Task Treeが展開、複数サブタスクが並列実行
Result      → 完了ステータス + 監査/トラッキングインターフェース
Close       → ブランドカード
```

適用：開発者向けテクニカル機能。ターミナル美学、等幅フォント、コードdiffハイライト。

### 3.2 5つの特殊ナラティブバリエーション

| バリエーション | 代表ビデオ | ビュー数 | コア手法 |
|---------------|-----------|---------|---------|
| コマンドと実行 | Computer Use | 77.9M | 左から右：スマートフォン → 処理フロー → デスクトップ |
| ギャラリーリビール | Claude Design | 63.5M | 抽象から複雑への段階的リビール |
| ターミナルナラティブ | Managed Agents | 21.6M | CLIコマンドと出力でストーリーを語る |
| 感謝の瞬間 | Thank You | 12.7M | 8.2秒ミニマル感情共鳴 |
| エコシステムスキャン | Office GA | 27.7M | Excel → PowerPoint → Wordを順番に表示 |

### 3.3 オープニングとクロージングの鉄則

**オープニング：**
- ロゴイントロなし——プロダクトが最初の2秒で直接表示
- 最初の2秒で視覚的アトラクションが必須
- 50%ブランド背景 + テキストフェードイン、30% UIウィンドウ具現化

**クロージング：**
- ブラックスクリーンへのハードカットなし
- 従来のCTAエンディングカードを使用しない（大多数）
- コンテンツで終了またはウォーム背景 + ロゴフェードアウト
- 「ハイエンド、自信」のブランドポジショニングを強化

## 4. トランジションとモーション文法

### 4.1 トランジションルール

**鉄則：ハードカットが主、派手なトランジションはゼロ。**

| トランジションタイプ | 使用頻度 | シーン |
|-------------------|---------|------|
| ハードカット | ~60% | シーン間切り替えの主要方式 |
| ウォーム背景へのフェードアウト | ~15% | ブランドクローズ、リズム転換 |
| スライドイン（水平/垂直） | ~10% | パネル展開、サイドバー |
| ドローアニメーション | ~5% | アイコンリビール、ストローク接続 |
| UIへのズーム | ~5% | オーバービューからディテールへ |
| ディゾルブ/スローフェードイン | ~0% | **一切使用しない** |

すべてのトランジションは2秒以内に制御。3Dフリップ、モーフィング、パーティクル効果なし。

### 4.2 コアモーション語彙

**カーソルシミュレーション（Cursor Simulation）**
```
タイムライン：
  -0.46s: 起点設定, opacity: 0→1
  -0.38s: ターゲットへ飛行, ease: power3.out
   0.00s: 到達, clickPulse アニメーション
  +0.12s: 軽微スケール (yoyo)
  +0.82s: カーソルフェードアウト
```
重要：カーソルは「先回り」で到達すべき、もたもたしない。

**Task Sequence — Magic Moment のコア**
```
入場  → 要素が下からスライドイン, opacity: 0→1, 0.28s
変色  → ステータスサークルがグレーからグリーンへ, 0.16s
チェック  → チェックマークが出現, 0.10s
```
各タスク行は独立したタイミングで、スタッタリング可能（stagger 0.05s）。

**モーダル入場（Modal Entrance）**
```
開始: y:34, scale:0.965, opacity:0
アニメーション: y→0, scale→1, opacity→1, 0.42s, ease: back.out(1.35)
```

**スタッタードリビール（Staggered Reveal）**
```
y:16 → y:0, opacity: 0→1, 0.28s, stagger: 0.05s
```
インテグレーションリスト、ファイルリスト、ツールカードに使用。

**ドローオン（Draw-on）**
```
SVG stroke-dasharray:
  strokeDashoffset: 200 → 0, 0.8s, ease: power2.inOut
```
用途：手描き落書きで2つのUI領域を接続、アイコンが線画から塗りへ。

### 4.3 カメラ移動ルール

**デフォルト：画面安定、持続ドリフトなし。**

カメラ移動は明確なナラティブ目的のためにのみ使用：
- 全体pan/zoomでプロダクト領域にフォーカス、所要時間0.3-0.6s
- プロダクト画面または領域全体をzoom、単一ボタンだけの拡大はしない
- カメラが到達後は安定を維持、UIテキストとステータスが読みやすいように
- シーン間はハードカット、レイヤー切り替え、コンテンツアニメーション入場が主

### 5.1 5つのオープニング戦略

| 戦略 | 手法 | 効果 | 代表ビデオ |
|------|------|------|-----------|
| **極端ミニマル** | 巨大ネガティブスペース + 極小アイコン | 好奇心最强、滞留率最高 | Computer Use (77.9M), Design (63.5M) |
| **ブランドリビール** | ウォーム背景 + 要素フェードイン | 抑制的、ハイエンド、一貫性 | 多数の標準機能ビデオ |

77.9M と 63.5M の2つの最高ビュー数ビデオが同じ戦略を使用：

2. テキスト一切なし——視聴者に「これは何か」を「解読」させる
3. 2拍目（0.8-1.2秒後）：機能名テキストリビール

**原理：** 極端ミニマル → 認知ギャップ → 好奇心 → 滞留 → 完視聴。

## 6. リズムエンジン

### 6.1 シーン所要時間ルール

| ビデオタイプ | シーン所要時間 | リズム感 |
|------------|-------------|---------|
| 長機能デモ（60-96s） | 4-8s/シーン | 計量的、チュートリアル式 |
| 中機能デモ（40-60s） | 3-5s/シーン | 中速、ストーリー式 |
| 短いアナウンス（<20s） | 2-3s/シーン | 迅速、力強い |
| ソーシャルショートカード（<12s） | 単一シーン | 最小限 |

### 6.2 所要時間とエンゲージメントの関係

**直感に反する発見：所要時間自体がエンゲージメントを決定しない。**

- 最高エンゲージメントのビデオは73秒（Computer Use）と81.5秒（Design）
- 10秒のビデオが10Mビューを獲得（Remote Control）
- 96秒のビデオが12.5Mのみ（Excel/PowerPoint）

**エンゲージメントを本当に決定するのは：**
1. オープニングフックの品質（最初の3秒）
2. 機能の汎用性（専門分野を越えた吸引力）
3. ナラティブリズム（もたもたしない、各シーンに情報密度）
4. ビジュアル精緻度（4K vs 1080p は相関あるが因果ではない）

### 6.3 Magic Moment の位置

**Magic Moment は最初の15秒以内に出現しなければならない。**

Magic Moment は「システムがユーザーに代わって何を完了しているか」のビジュアライゼーション瞬間——ローディングスピナーではなく：
- タスクが1行ずつ完了（グリーンチェック）
- ファイルが自動生成
- ターミナルコマンドが自律実行
- データが複数アプリ間を流転

15秒以内に視聴者に「ワオ」の瞬間を与えなければ、彼らはスクロールして去る。

## 7. エンゲージメント公式

### 7.1 高エンゲージメントビデオの5つの共通特徴

77本のビデオのデータから抽出：

1. **4K解像度** — 3840x2160 と高ビュー数の強い相関
2. **極端ミニマルオープニング** — 好奇心駆動の滞留
3. **汎用機能** — 専門分野を越えた吸引力、開発者だけでなく
4. **70-80秒のリズム型ナラティブ** — 視聴者はフル機能デモを見切る意思がある
5. **空間/水平ナラティブコンポジション** — 左から右へのビジュアルフロー

- 所要時間自体（短ければ良いわけではない）
- アスペクト比（横向き縦向き両方に高低あり）
- 開発者フォーカスかどうか（Code Review 23.5M）
- 制作コスト（ライブビデオ 14.6M vs 高品質ビデオ 2M）

| 高 | 10-30M | ~15% | 高品質制作、明確な機能デモ、強いナラティブ |
| 中 | 2-10M | ~40% | 標準制作、中程度のナラティブ |
| 低 | <2M | ~42% | 情報密度が低いまたは対象が狭い |

78本のビデオの分析から抽出——これらはClaudeが行っておらず、あなたも行うべきでないこと：

9. **持続ドリフトカメラは使わない** — 短く明確なpan / zoomのみ実行

## 10. 時系列変遷分析：8ヶ月で再生数18倍

### 10.1 データ全景

| 時期 | ビデオ数 | 平均再生 | 最高再生 | 総再生 |
|------|---------|---------|---------|--------|
| 2025 Q4 | 21 | **0.7M** | 2.7M | 14M |
| 2026 Q1 | 41 | **9.1M** | 77.9M | 373M |
| 2026 Q2 | 15 | **12.6M** | 63.5M | 190M |

8ヶ月で平均再生数が18倍。これは偶然のバズヒットではなく——方法論の反復である。

### 10.2 3つのステージの質的変化

#### 2025 Q4 — 「ビデオが作れるようになった」

始動期。制作は粗雑だが基礎言語を確立：
- ブランド背景上のフローティングアプリウィンドウ（PPTアニメーションのよう）
- テラコッタ + ダークモードが標準として確立
- セリフ体タイトル + 文節式大文字小文字＋ピリオド
- 実人物出演は1本のみ（Opus 4.5エンジニア）
- 最高再生2.7M（Claude Code on Web）

**特徴：安全——すべてのビデオが同じように見える、テンプレートで作ったよう。**

#### 2026 Q1 — 「バズの公式が見つかった」

質的変化のステージ：
- フローティングウィンドウから**3Dデバイスmockup**へ進化（スマートフォン/ノートPC/ディスプレイがウォーム背景に合成）
- 「Keep Thinking」ブランド哲学が登場——機能を売るから態度を売るへ
- Coworkシリーズが「非技術者のAIワークフロー」ナラティブを定義
- **2つのイベント級バズ：** Coworkローンチ（49.7M）、Computer Use（77.9M）
- セキュリティ関連ビデオ26.2M——「セキュリティ」という言葉自体に伝播力あり
- ライブビデオ（Coworkデモ、14.6M）が「リアル感」が「精緻感」より強いことを証明

**重要な発見：制作が精緻であれば良いのではなく、ナラティブが強ければ良い。**

#### 2026 Q2 — 「少即是多」が検証された

最終ステージの進化は引き算：
- 極端ミニマルオープニングが最強Hookに（Computer Useはカーソルアイコン1つ + 大きな空白）
- Claude Design（63.5M）が線画パレットアイコンでオープニング、何であるかをまず教えない
- 空間ナラティブが成熟：左から右のビジュアルフロー（スマートフォン → 処理 → デスクトップ）
- 手描き落書きコネクターがシグネチャーエレメントに
- Office GA（27.7M）が「エコシステムスキャン」ナラティブを表示

**コア洞察：最初の2秒で与える情報が少ないほど、視聴者は長く留まる。**

### 10.3 ナラティブ立場の変遷

```
Q4 2025: "見て、ClaudeはXができる"           → 説明型
Q1 2026: "想像して、あなたは一言言うだけでいい"   → 表示型
Q2 2026: "（静かに表示し、話さない）"        → 暗示型
```

「説明型」から「表示型」から「暗示型」へ——ブランドポテンシャルエネルギーが越来越高くなり、ビデオが越来越静かに。

### 10.4 リリースリズム分析：パルス式リリース戦略

**全体データ：77本のビデオ、222日、平均2.9日に1本。**

しかし「平均」は誤解を招く——Anthropicのリリースは均等分布ではなく、密集パルス + 長間隔のリズム。

#### 月次分布

| 月 | ビデオ数 | 特徴 |
|----|---------|------|
| 2025-10 | 5 | 始動、週1本 |
| 2025-11 | 5 | 安定、週1本 |
| 2025-12 | 11 | 加速、年末ラッシュ |
| 2026-01 | 9 | 安定高め |
| 2026-02 | **23** | **爆**爆発月——総量の30%** |
| 2026-03 | 9 | 落下したが高位を維持 |
| 2026-04 | 10 | 安定 |
| 2026-05 | 5 | 月初から現在まで（データは5月10日時点） |

**2026年2月が重要な転換点**——1ヶ月で23本のビデオをリリース、全77本の30%を占める。これは偶然ではない：Opus 4.6リリース、Sonnet 4.6ローンチ、Coworkシリーズ密集プロモーション、ハッカソンイベント全てがこの月に集中。

#### 222日中わずか51日にビデオリリースあり

つまり **77%の日は「空白日」**——ビデオを一切リリースしない。リリース密度は線形ではなく、パルス式。

#### 3つの密集リリースキャンペーン

| キャンペーン | 時間 | 日数 | ビデオ数 | 重要なコンテンツ |
|-------------|------|------|---------|---------------|
| Opus 4.6 リリース週 | 2月2-6日 | 5日 | 9本 | Opus 4.6、Sonnet 4.6、機能マトリックス |
| Coworkプロモーション週 | 2月17-20日 | 3日 | 10本 | Cowork機能シリーズ、ライブデモ、2/20 単日7本 |
| Q1フラッグシップ週 | 3月23-25日 | 3日 | 3本 | Computer Use（77.9M）、Design（63.5M）、合計93.1M |

**第3回キャンペーンが最も極端**——3日で3本のビデオ、しかし総再生93.1M。品質 > 数量の完璧な検証。

#### 最長間隔

| 間隔 | 期間 | 時帯 |
|------|------|------|
| 最長 | 28日 | 2025-10-28 → 2025-11-25 |
| 次長 | 19日 | 2025-12-29 → 2026-01-17 |
| 第3 | 14日 | 2025-11-11 → 2025-11-25 |

これらの長間隔は初期（Q4 2025）に出現、チームがまだリズムを模索していたことを示す。2026年Q1-Q2になると、最長間隔は7-10日に短縮。

#### パルス戦略の根底ロジック

```
通常期：週1-2本のビデオ、ブランドプレゼンスを維持
     ↓
プロダクトリリース：密集3-5日、毎日2-3本のビデオ、情報密度を演出
     ↓
クールダウン期：通常リズムに戻る
```

**なぜ均等配信ではなくパルスなのか？**

1. **アルゴリズム効果**——ソーシャルプラットフォームのアルゴリズムは「トピック集中度」を評価、短時間に複数ビデオ = より多くのフィードにプッシュされる
2. **ナラティブ密度**——1つの大きな機能を3-5本のビデオで異なる角度から表示、単一ビデオより広いカバレッジ
3. **チームリズム**——ビデオ制作はバッチ作業、一度にまとめて作る方が毎日少しずつ作るより効率的
4. **ユーザー認知**——「最近あちこちにClaudeがある」方が「毎週安定して1本」よりインパクトあり

**実践的示唆：** 毎日ビデオをリリースすることを目指さない。まとめを集め、3-5日間に集中リリースし、その後静かなリズムに戻る。パルス > 均等。

#### リリース時間帯分析（時間単位、PSTタイムゾーン）

77件のツイートのsnowflake IDから正確なリリース時間を抽出、太平洋標準時（PST）で統計：

**リリース時間帯分布：**

| 時帯（PST） | ビデオ数 | 平均再生 | 意味 |
|------------|--------|---------|------|
| 深夜 0-6時 | 10 | **13.1M** | 事前スケジュールリリース |
| 朝 6-9時 | 33 | 6.3M | **主力リリースウィンドウ**（43%のビデオ） |
| 午前 9-12時 | 24 | 8.4M | サブ主力ウィンドウ |
| 午後 12-15時 | 10 | 3.8M | テールリリース |

**77本のビデオが全てPST 04:00-14:00の10時間以内に集中。** 午後3時以降はゼロリリース。

**時間単位の精確分布：**

| 時間（PST） | ビデオ数 | 平均再生 | 代表ビデオ |
|------------|--------|---------|---------|

### 11.2 5つのバズ法則

#### バズ法則一：コンテンツ > 制作

**バズのキーワードは「新しい可能性」であり、「機能更新」ではない。**

- Top 10 全てが「Introducing...」または「You can now...」——**初回発表**
- Bottom 10 全てが「now available on...」、「is now in beta」——**既存機能の拡張**

| コンテンツタイプ | 平均再生 | 例 |
|---------------|---------|-----|
| 全新プロダクト/能力の初回発表 | **30M+** | Computer Use、Design、Cowork |
| 主要機能更新 | **5-15M** | Code Review、Security |
| プラットフォーム拡張/提携 | **1-5M** | Excel on Pro、Chrome |
| 増分更新/小機能 | **<1M** | Skills Dir、/stats、guest passes |

**人々は「新種」に支払い、「バージョン更新」には支払わない。**

#### バズ法則二：対象範囲が天井を決定

Top 10の機能は全て専門分野を超えた汎用：
- Computer Use（77.9M）—— 全員が「AIがあなたのPCを操作する」を理解できる
- Cowork（49.7M）—— Claude Codeの10倍の対象範囲
- Office GA（27.7M）—— 全世界のOfficeユーザー

Bottom 10は全てニッチ機能：
- Skills Directory（77K）—— 既存ユーザーのみ関心あり
- Guest Passes（62K）—— Maxユーザーのみ関心あり
- /statsコマンド（70K）—— CLIユーザーのみ関心あり

**100万人にしか意味のないトピックは、制作が精緻でも1億人に意味のあるトピックには勝てない。**

#### バズ法則三：60-80秒がスイートスポット

| 所要時間帯 | Top 10割合 | 特徴 |
|-----------|-----------|------|
| 40-50s | 3/10 | 機能フォーカス、高速デモ |
| 60-80s | 4/10 | 完全なナラティブ、DemoとMagic両方 |
| 80-90s | 2/10 | エコシステム表示、複数プロダクト連携 |

**短ければ良いわけではない。** Bottom 10平均35秒、Top 10平均67秒。ショートビデオの問題は「短すぎる」ではなく「情報密度が低すぎる」——35秒で「now available on Android」しか言っていない、見るべきデモがない。

#### バズ法則四：感情 > 機能（時折）

**最高いいね率（likes/views）のビデオはTopビデオではなくBottomビデオ。**
- Top 10平均いいね率：0.22%
- Bottom 10平均いいね率：0.60%

Bottomビデオはコアユーザーにリーチ——彼らは元々@claudeaiをフォローしているので、自然にいいねする。Topビデオは一般層にリーチ——大部分は通りすがり。

しかし例外がある：**「Thank You」（8.2秒、12.7M、いいね率0.38%）**。内容は「次の2週間、ピーク時間帯の使用量が2倍になります」の一文のみ。新機能なし、ただのお礼。

**「感謝される」のは希少体験。** ほとんどの企業がビデオで「新機能を見て」と言い、Anthropicは「ありがとう」と言った。

#### バズ法則五：ライブ > 精緻（時折）

Coworkライブデモ（14.6M）は最も粗雑な制作のビデオ——実際の人物が寮でスクリーン録画。しかし多くの4K精緻ビデオより高い再生数を獲得。

**完璧なmockupだらけのフィードの中で、「本物」のものは希少。** 精緻ビデオを作るなと言っているわけではない——時折ライブコンテンツを織り交ぜることで化学反応が生まれる。

### 11.3 バズ優先度

影響力順：
1. **「新種」コンテンツ** — 全新能力の初回発表
2. **対象範囲** — より多くの人が理解できるほど良い
3. **極端ミニマルオープニング** — 最初の2秒の情報が少ないほど良い
4. **60-80秒リズム** — 十分に展開、もたもたしない
5. **感情トリガー** — 「見て機能」より「ありがとう」が時折より強力
6. **リアル感の織り交ぜ** — 精緻ビデオフィードの中にライブビデオを1本


## 12. データ駆動の多次元分析

77本のビデオの構造化データを使い、エンゲージメント率、解像度、所要時間、リリース日、コンテンツキーワード、バイラリティ、実用性の7つの次元でクロス分析し、Anthropicビデオマーケティングのデータ法則を抽出。

### 12.1 エンゲージメント率次元：誰が本当に参加しているか

エンゲージメント率 = エンゲージメント数 / 再生数。絶対値よりコンテンツ品質を反映——「アルゴリズムが通りすがりにプッシュしたが通りすがりは無感動」というノイズをフィルタリングするから。

| 指標 | 公式 | 意味 |
|------|------|------|
| いいね率 | likes / views | 即時認可 |
| ブックマーク率 | bookmarks / views | 「これは有用、後で見る」 |
| リツイート率 | retweets / views | 「他の人にも見てほしい」 |
| リプライ率 | replies / views | 「議論したい」 |

**重要な発見：高再生数 ≠ 高エンゲージメント率。**

- **ブックマーク率最高**のビデオはバズではなく開発者コンテンツ：Built with Opus 4.6（0.47%）、Code with Claudeカンファレンス（0.35%）、ハッカソン（0.34%）、Agent View（0.32%）
- **リプライ率最高**もニッチ寄り：Claude Code実行可能（0.045%）、Claude for Public（0.041%）
- **いいね率最高**はOpus 4.6関連コンテンツ（1.46%）とClaude Code周年（1.19%）

**解釈：** 開発者グループは人数こそ少ないが、参加深度は一般層を大きく上回る。ブックマーク率が高い = 「これはツール、使う」。Claudeのビデオが2つのグループを同時にサービスしていることを示す：一般層は再生数を見、コアユーザーはエンゲージメント深度を見る。

### 12.2 解像度次元：4Kは相関あるが因果ではない

| 解像度 | ビデオ数 | 平均再生 | 最高再生 |
|--------|--------|---------|---------|
| 3840x2160 (4K) | 16 | 9.2M | 77.9M |
| 1920x1080 (1080p) | 40 | 8.5M | 63.5M |
| その他解像度 | 21 | 1.7M | 26.2M |

- 4Kと1080pの平均再生差は小さい（9.2M vs 8.5M）
- **第2位の高再生ビデオ（Design、63.5M）は1080p、4Kではない**
- 「その他解像度」は平均1.7Mのみ——しかし大部分が初期ビデオまたは特殊フォーマット（縦向き、正方形）

**実践：** 4Kを優先するが、リソースが限られている場合、1080pはパフォーマンスを明らかに下げない。本当に重要なのはコンテンツ品質とナラティブ、ピクセル数ではない。

### 12.3 所要時間次元：60-90秒がスイートスポット

| 所要時間帯 | ビデオ数 | 平均再生 | いいね率 | ブックマーク率 |
|-----------|--------|---------|--------|-------------|
| <15s | 13 | 3.0M | 0.56% | 0.17% |
| 15-30s | 7 | 1.9M | 0.54% | 0.20% |
| 30-60s | 27 | 7.3M | 0.43% | 0.15% |
| **60-90s** | **19** | **15.6M** | **0.48%** | **0.13%** |
| >90s | 11 | 2.9M | 0.55% | 0.19% |

**60-90秒の平均再生（15.6M）は他の全時間帯の2-8倍。**

しかし>90sは2.9Mに急落。これは：
- 短すぎる（<30s）：情報密度が不十分、完全なDemoがない → 再生低い
- 60-90s：完全なナラティブを展開するのに十分（Hook → Demo → Magic → Result） → 再生最高
- 長すぎる（>90s）：注意力減衰、コンテンツが特に密集でない限り → 再生回落

**ブックマーク率は長くなるほど低下**：ショートビデオのブックマーク率が高い（<15sで0.17%、60-90sで0.13%のみ）。ショートビデオ = 高速消費、ロングビデオ = 見終わったら去る、ブックマークしない。

### 12.4 リリース曜日次元：月曜と金曜が最強

| 曜日 | ビデオ数 | 平均再生 | 総再生 |
|------|--------|---------|--------|
| **Monday** | **15** | **12.6M** | **189.5M** |
| Tuesday | 17 | 5.5M | 93.6M |
| Wednesday | 16 | 4.7M | 74.8M |
| Thursday | 13 | 5.1M | 65.9M |
| **Friday** | **15** | **9.4M** | **141.0M** |

- **月曜が平均再生最高（12.6M）** — 週末後の最初の営業日、ユーザー活発度が高い
- **金曜が次（9.4M）** — 「金曜リリース、週末発酵」の伝播パターンに関連する可能性
- 土曜は1本のみ（Thank You、12.7M）、サンプルが小さすぎて結論不可
- 火曜から木曜は相対的に平淡

**実践：** 主要リリースは月曜または金曜を選択。通常更新は火曜から木曜でプレゼンスを維持。

### 12.5 コンテンツキーワード次元：どのトピックに伝播力があるか

| キーワード | 意味 | ビデオ数 | 平均再生 |
|----------|------|--------|---------|

| now available | 機能上线 | 8 | 4.6M |

**「Introducing」は再生数の絶対的保証**——平均23.6M、「now available」（4.6M）の5倍。

これは第11章の発見を検証：**初回発表 >> 機能拡張**。「Introducing」は「新種」を暗示し、「now available」は「古いものが新しい場所に」を暗示。

**トピック吸引力ランキング：**
1. デザイン（19.7M）—— 専門分野を超えた汎用、非技術ユーザーも関心
2. Cowork（17.7M）—— 「非プログラマーもAIを使える」、対象範囲が極めて広い
3. Excel（16.1M）—— グローバルOfficeユーザーベース
4. セキュリティ（15.5M）—— 「セキュリティ」は自体に不安感と注目度がある
5. Claude Code（9.9M）—— 開発者専用、対象は狭いが忠誠度が高い

### 12.6 バイラリティ vs 実用性：2つの全く異なるシグナル

**リツイート率が高い = 「他の人にも見てほしい」（バイラリティ）**

| ランク | コンテンツ | リツイート率 | 再生 |
|-------|---------|-----------|------|
| 1 | Claude for Public | 0.098% | 0.1M |
| 2 | Code with Claude カンファレンス | 0.094% | 1.1M |
| 3 | Claude Code 周年 | 0.078% | 0.8M |
| 4 | Built with Opus 4.6 | 0.077% | 1.0M |
| 5 | Ads are coming to AI | 0.076% | 5.2M |

**ブックマーク率が高い = 「これは有用、後で使う」（実用性）**

| ランク | コンテンツ | ブックマーク率 | 再生 |
|-------|---------|------------|------|

- 大衆バズ（77.9M Computer Use）のリツイート率とブックマーク率は突出していない——人々は見て、驚いて、スクロールして去った

- **深度インパクト**：ブックマーク率とリプライ率を見る → Agent View（0.32% bm、686 replies）

### 12.7 総合エンゲージメントスコア：加重評価

異なるエンゲージメント行動に異なるウェイトを付与（ブックマーク = 3x、リプライ = 5x、リツイート = 2x、いいね = 1x）、総合エンゲージメントスコアを計算：

```
総合スコア = (likes + bookmarks×3 + retweets×2 + replies×5) / views × 100
```

**Top 5 総合エンゲージメント：**

| ランク | コンテンツ | 総合スコア | 再生 | L | B | RT | R |
|-------|---------|---------|------|---|---|----|---|
| 1 | Built with Opus 4.6 | 2.70% | 1.0M | 9.9K | 4.9K | 800 | 370 |
| 2 | Code with Claude カンファレンス | 2.39% | 1.1M | 10.8K | 3.9K | 1,057 | 460 |
| 3 | Agent View | 2.13% | 2.3M | 20.3K | 7.3K | 1,571 | 686 |
| 4 | Claude Code 周年 | 2.04% | 0.8M | 9.7K | 1.4K | 641 | 310 |
| 5 | ハッカソン | 2.01% | 1.6M | 10.7K | 5.5K | 937 | 622 |

**法則：総合スコア最高のコンテンツに共通の特徴——開発者またはコミュニティイベント向け。** 再生数は高くない（0.8M-2.3M）が、見た人は全員深度参加した。

**これはマーケティング戦略に2つのパスを提供：**
1. **幅広路線**：汎用機能ビデオを作成、再生数とブランド露出を追求（Computer Use、Design、Cowork）
2. **深度路線**：開発者/コミュニティコンテンツを作成、ブックマーク率と議論度を追求（Agent View、ハッカソン、Built with Opus 4.6）

両方の路線を持つべき——幅広で新規獲得、深度でリテンション。


## 13. 競合ビデオ戦略比較

### 13.1 4大AI企業のビデオ言語差異

| 次元 | Anthropic (Claude) | OpenAI (ChatGPT) | Google (Gemini) | Apple (Apple Intelligence) |

### 13.2 Claudeの差別化戦略解釈

**なぜウォームカラーを選んだのか？**
AIプロダクトのデフォルトビジュアル言語はクールカラー（ブルー/ブラック）——「テクノロジー感」と「インテリジェンス」を伝える。Anthropicは逆：ウォームカラーは「思考」「学術」「人文」を伝える。これは美的嗜好ではなく、ブランドポジショニングのビジュアル表現：Claudeは「考えるAI」であり、「計算するマシン」ではない。

**なぜ実人物をほとんど使わないのか？**
78本のビデオ中1本のみ実人物の顔あり。理由：
- 実人物は注意を散らす——視聴者が「この人」に注目し始め、「この機能」に注目しなくなる
- UI/テキスト/モーション自体がブランド個性を表現できる
- 実人物なし = 無限のスケーラビリティ——人事異動の影響を受けない
- 例外：「信頼传递」が必要な場合（エンジニアがOpus 4.5を語る）、実人物を導入

**なぜエンディングCTAを使わないのか？**
従来のビデオマーケティングはCTA（"Sign up now!"）で緊急性を演出。Claudeは使わない：
- CTAは「視聴者を必要としている」シグナル——ブランドポテンシャルエネルギーを低下
- ロゴへのフェードアウト = 「プロダクトは自明」——ブランドポテンシャルエネルギーを向上
- これは**希少性シグナル**：求めないほど、見たくなる

### 13.3 「Keep Thinking」ブランド哲学として

「Keep Thinking」は単なるスローガンではなく、ビデオ戦略全体の根底ロジック：
- ロゴイントロなし → 「自己紹介は不要」
- エンディングCTAなし → 「説得する必要なし」
- ダークモードUI → 「真剣な環境で仕事をしている」
- ミニマルオープニング → 「考える空間を与える」
- 抑制的モーション → 「判断を妨げない」

すべての制作決定がこのブランド哲学に遡及できる。これは方法論の最高層——「どうするか」ではなく「なぜそうするか」。

## 14. エンゲージメント心理学：なぜこれらのパターンが有効か

### 14.1 「少即是多」の認知ギャップ原理

77.9M と 63.5M の2つの最高再生ビデオが極端ミニマルオープニングを使用。原理：

```
ミニマル画面 → 情報不足 → 認知ギャップ → 脳が自動補完 → 好奇心 → 滞留視聴
```

これは**情報ギャップ理論（Information Gap Theory）**の応用：
- 脳は未完了のパターンを嫌う
- 画面に極小アイコン + 大きな空白しかない時、脳はこの画面を「理解」するために強制的に働く
- この認知投資が感情接続を生む——視聴者はすでに注意を「投資」しており、放棄したくない

**実践：** フレーム1には1つの要素のみ配置、テキストなし。0.8-1.2秒後にテキストをリビール。

### 14.2 「プロセスビジュアライゼーション」の信頼構築

なぜプロセスビジュアライゼーション（タスクリスト、ターミナル出力）が結果のみ表示するより高エンゲージメントを得るのか？

- **透明性 = 信頼**：AIが「何を考えているか」を表示することは「完了しました」と言うより説得力がある
- **遅延満足**：視聴者がプログレスバーが進むのを見て、「もうすぐ完了」の期待感が生まれる
- **検証可能性**：ターミナル出力、コードdiffが視聴者に「これは本物、デモではない」と感じさせる

**実践：** 生成プロセスをスキップしない。Task Sequence、プログレスインジケーター、ターミナルスクロールでビジュアライズする。

### 14.3 「空間ナラティブ」の読解本能

左から右のビジュアルフロー（スマートフォン → 処理 → デスクトップ）がなぜ有効なのか？

- 横並びテキストの読解方向が左から右（英語/中国語横並び）
- 脳は「左から右」を「因果関係」または「時間経過」として理解
- この暗黙のタイムラインが認知負荷を軽減——「何を先に、後に」を追加説明する必要がない

**実践：** 複数ステージがある場合、番号や矢印ではなく左から右の空間レイアウトでフローを暗示する。

### 14.4 ハードカットトランジションの心理効果

なぜClaudeはほぼハードカットのみ使用し、スローディゾルブ/グラデーションを一切使わないのか？

- **ハードカット = 自信**：もたもたせず、「すべての画面が留まる価値がある」ことを暗示
- **ディゾルブ = 不確実**：ディゾルブは「この画面は留まる価値がない、早く通り過ぎよう」を暗示
- **リズム感**：ハードカットはビート感を生む、音楽のドラムビートのように
- **モダン感**：スローディゾルブは2000年代の美学——今使うと古く見える

## 15. オーディオ/BGM戦略

### 15.1 5つのビデオタイプのオーディオ方案

| ビデオタイプ | BGMスタイル | ボイス | 参考根拠 |
|------------|-----------|--------|---------|
| 高速リズム動画 | ビート同期エレクトロニック/パーカッション | なし | Coworkリリース（49.7M） |
| プロダクトデモ | 環境軽音楽 | なしまたはナレーション | 多数の機能ビデオ |
| ターミナル/開発者 | 最小限または無音 | なし | Agent View, Managed Agents |
| ブランドステートメント | 単一トーンまたは無音 | ありの可能性 | "Keep Thinking" |
| ライブ/実人物 | ボイスナレーション | あり | Coworkライブデモ |

### 15.2 オーディオ制作原則

1. **無音版を保持** — BGMなしの純ビジュアル版を先に完成させ、別途音楽をオーバーレイ
2. **音楽が画面を奪わない** — BGMはリズムを強化するもの、ナラティブを主導するものではない
3. **オープニング/エンディングのフェードイン/アウト** — 音楽の突然の開始/終了を回避
4. **ビートアラインメント** — 高速リズムビデオのシーン切り替えは音楽ビートに合わせるべき
5. **無音でも視認可能** — ソーシャルプラットフォームでは大部分の再生が無音、ビデオは無音状態でも情報を伝えなければならない

## 16. 実践チェックリスト

### 16.1 制作前チェック

- [ ] ビデオタイプの決定（モード A/B/C/D）
- [ ] 所要時間予算の確定
- [ ] ターゲットチャネルとアスペクト比の確認

- [ ] 全UIが再構築された完璧版、実際のスクリーン録画ではない
- [ ] 無関係なUIを除去：デバッグ枠、余計なタブ、無関係な通知バー

- [ ] タイトルは文節式大文字小文字＋ピリオドを使用
- [ ] ロゴイントロなし
- [ ] カーソル移動が自然（先回りで到達）
- [ ] カメラに持続ドリフトなし
- [ ] 単一ボタンだけの拡大なし

### 16.3 制作後チェック

- [ ] エンディングCTAカードなし
- [ ] ブラックスクリーンへのハードカットなし
- [ ] 最終フレームにブランド表示あり
- [ ] 無音状態で情報を伝えられる

- [ ] 複数解像度で書き出し（4K + 1080p）

- [ ] X/Twitter：16:9 または 1:1、最初の3秒が滞留を決定

- [ ] リリース時間：ターゲットオーディエンスの活発時間帯に従う

## 17. 適応ガイド：自社プロダクトへの応用方法

### 17.1 直接再利用可能なもの

| Claudeのやり方 | 汎用原則 | 直接使用可能 |
|-------------|---------|------------|
| ハードカットが主 | トランジション抑制化 | 直接使用 |
| ロゴイントロなし | 最初の2秒でプロダクト表示 | 直接使用 |
| エンディングCTAなし | コンテンツで終了 | 直接使用 |
| 文節式タイトル＋ピリオド | 会話感コピー | 直接使用 |
| ウェイト500/600/700 | タイポグラフィ安定性 | 直接使用 |
| Task Sequence | プロセスビジュアライゼーション | 直接使用 |
| シーン3-8秒 | リズム緊密化 | 直接使用 |
| アンチパターンチェックリスト | 一般的なミス回避 | 直接使用 |

### 17.2 適応が必要なもの

| Claudeのやり方 | なぜそのまま使えないか | 適応方法 |
|-------------|-------------------|---------|
| ウォームホワイト + テラコッタ | Claudeブランドカラー | 自社ブランドメインカラーに置き換え、「ウォームキャンバス + ダークUI」の階層関係を保持 |
| ダークモード固定 | 自社プロダクトがライトUIの可能性 | プロダクトの実際のUI明暗を保持、外部キャンバスのみウォームカラーを使用 |
| セリフ体タイトル | 自社ブランドにセリフ体が合わない可能性 | 自社ブランドフォントを使用、「タイトル大 + 本文小」の階層を保持 |
| デバイスmockup合成 | 3Dレンダリング能力が必要 | スクリーンショット + シャドウにダウングレード、効果は劣るが敷居は大幅に低い |
| 極端ミニマルオープニング | ブランド認知度の裏付けが必要 | ブランドが知られていない場合、先に機能名を表示してからミニマルにする |

### 17.3 コア心法

Claudeの「外観」を模倣するのではなく、Claudeの「意思決定ロジック」を模倣する：

- **なぜウォームカラー？** → 競合が全てクールカラーを使用、差別化
- **自社バージョン：** 競合が使っていない色彩言語を見つける

- **なぜ実人物を使わない？** → UI自体がストーリーを語れる
- **自社バージョン：** UIが十分に美しくない場合、先にUIを修正してからビデオを作る

- **なぜCTAを使わない？** → ブランドポテンシャルエネルギーが十分高い
- **自社バージョン：** ブランドが知られていない場合、適度なCTAは合理的

- **なぜハードカットが主？** → すべての画面に価値がある
- **自社バージョン：** あるシーンが3秒を支えられない場合、短縮するか削除する

**方法論の本質はルールチェックリストではなく、「すべての決定に理由がある」こと。**
